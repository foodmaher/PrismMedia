# v2.9 safe staged-readback test

This build connects ETS2's independent park-camera render to the selected GPS
without returning to the v2.8 render-target architecture that caused the
loading-screen device-removal crash.

## Safety design

- The GPS replacement remains a dynamic, CPU-writable, shader-resource-only
  texture.
- The plugin never binds the GPS as a render target.
- The plugin never copies into an engine-owned render target.
- Three small 256x256 staging textures receive copies of the park output.
- CPU mapping always uses `D3D11_MAP_FLAG_DO_NOT_WAIT`.
- If the GPU has not finished a staging copy, the frame is skipped.
- Resources and readback work are created only after reverse or Preview is
  requested.

## First test

1. Load the same truck that passed the v2.8.1 hotfix.
2. Open **Automatic Reverse Camera**.
3. Select **Internal park camera (safe staged test)**.
4. Enable **Preview / calibrate now** while stationary.
5. Wait two seconds.
6. Confirm the menu changes from `readback: waiting` to `readback: ready`.
7. Close the menu, select reverse, and verify that normal media returns after
   leaving reverse.

The menu reports decoded frames and `busy skips`. An occasional busy skip is
intentional and means the non-blocking protection is working.

If the GPS displays the wrong 256x256 intermediate image, keep the game open,
capture a screenshot of the plugin menu, and provide `game.log.txt`. Target
selection can then be narrowed without changing the GPS resource architecture.
