# v2.8.1 loading-crash hotfix

This build fixes the loading-screen crash introduced by the experimental v2.8
GPU park-camera output.

## What the supplied crash log showed

- The GPS replacement texture was created successfully.
- The dormant ETS2 park-camera slot was installed successfully.
- The D3D11 device was removed (`DXGI_ERROR_DEVICE_REMOVED`, `0x887A0005`)
  when ETS2 resized its swap chain to 1920x1080.
- The failure occurred before a park-camera colour target was captured, so the
  crash was in the new GPS render-target architecture rather than the saved
  configuration, media client, or truck.

## Safety change

v2.8.1 restores the stable v2.7 GPS texture path:

- dynamic, CPU-writable BGRA texture;
- shader-resource binding only;
- no second upload texture;
- no per-frame `CopyResource` into a game-sampled GPS texture;
- no GPS render-target view;
- no engine render-target reference capture.

The dormant internal park camera can still be activated and traced, but its GPU
image is not copied to the GPS in this hotfix. Select **Calibrated window
capture** if you need a working reverse picture while the internal readback-safe
bridge is being validated.

## Installation

Replace only `PrismTextureStreamerFB.dll` with the v2.8.1 build. Keep
`PrismMediaClient.exe`, its WebView2 files, and the optional SPF companion from
the previous package.

If the game was left in fullscreen after the crash, the hotfix is designed to
survive the same fullscreen/window resize. You do not need to delete the saved
plugin configuration.
