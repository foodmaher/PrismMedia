# v2.9.1 park-target selector test

The v2.9 screenshot and log prove that ETS2's internal park-camera slot is
scheduled, the GPU readback is stable, and frames reach the GPS. The flat grey
result is a different 256x256 HDR buffer from the same render pass rather than
a readback or GPS failure.

## What changed

- Distinct 256x256 `R11G11B10_FLOAT` targets are recorded as Candidate A-D.
- **Internal colour target** is saved in `config.ini`.
- Candidate A is the default for ETS2 1.60.1.7.
- Switching candidates keeps the three-buffer, non-blocking staging path.
- No candidate discovery or readback work runs while driving forward.

## Test

1. Install the newly built v2.9.1 package over v2.9.0.
2. Load the same truck and open **Automatic Reverse Camera**.
3. Enable **Preview / calibrate now**.
4. Leave **Internal colour target** on **Candidate A (recommended)** for two
   seconds.
5. If the GPS is still flat or grey, select Candidate B. Try C and D only when
   the menu reports that those buffers were found.
6. Keep the candidate that shows the independent rear view. The setting is
   saved automatically.

The menu reports both the number of matching buffers found and the active
candidate. Candidate switching has the same performance cost; only one selected
buffer is copied into the existing non-blocking staging ring.

If none of the discovered candidates contains a rear image, provide a screenshot
with the selector visible and the new `game.log.txt`. The next diagnostic can
then score or inspect the exact buffers without changing the crash-safe GPS
texture path.
