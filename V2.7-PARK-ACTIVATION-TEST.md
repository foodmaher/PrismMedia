# PrismTextureStreamerFB 2.7 Park-Camera Activation Test

## What this build proves

The first 2.6 runtime trace confirmed that ETS2 1.60.1.7 creates only camera
slots 0-5 for the tested truck. The executable nevertheless contains complete
resource definitions for dormant slots 7 (`park`) and 8 (`park_360`).

Version 2.7 safely tests slot 7:

- it clones an already initialized engine mirror-camera object into slot 7
  while the truck interior is loading;
- it lets ETS2's own resource initializer create the `park` render resource;
- it asks ETS2 to schedule that camera only during an explicit 10-second
  trace; and
- it recognizes both nominal render-target sizes and the user's
  `r_mirror_scale_x/y = 2` sizes.

The player's active camera is never changed. The GPS also keeps its normal
media image in this diagnostic stage.

## Safety guards

All internal changes remain disabled unless every check succeeds:

- executable timestamp `0x6A426DE5`;
- loaded image size `0x0382D000`;
- unique scheduler signature at RVA `0x00524DB0`;
- exact park-resource initializer bytes at RVA `0x00533400`;
- exact active-camera-mask bytes at RVA `0x00524170`;
- expected mirror-camera vtable at RVA `0x02196F90`; and
- expected virtual clone function at RVA `0x00846B30`.

Any failed layout check refuses activation and leaves the stable Window crop
method available.

## Run the test

1. Install the complete 2.7 package.
2. Start ETS2 in DirectX 11 mode and open the plugin with **Ctrl+F8**.
3. Open the target screen and **Automatic Reverse Camera**.
4. Enable **Show reverse view on this screen**.
5. Choose **Internal park-camera activation (experimental)**.
6. Let the configuration save, return to the profile/truck menu, and load the
   truck again. A full game restart is also acceptable.
7. Reopen the same menu. Confirm:
   - **Internal slot 7: installed**
   - **resource: ready**
8. Select reverse gear, or enable **Preview / calibrate now**.
9. Open **Internal render-to-texture probe** and click
   **Start 10-second RTT trace**.
10. Close the menu until the trace ends, exit ETS2 normally, and send back
    `Documents\Euro Truck Simulator 2\game.log.txt`.

Expected log lines include:

```text
[RTT park] Cloned the initialized front mirror camera into dormant slot 7.
[RTT park] Internal park resource: created (descriptor 256x256).
[RTT probe] Trace finished. ... slot mask=0x0BF, park schedules=...
```

The cloned camera initially keeps a known-valid engine placement. This trace
is for finding the exact engine-owned GPU texture. Trailer-tail placement and
the rear-facing orientation are applied only after that resource is verified.

## Performance

- Forward driving: no extra park-camera render.
- Reverse/Preview outside a trace: no extra park-camera render.
- During the 10-second trace: one additional engine camera can be rendered,
  plus diagnostic render-target bookkeeping. A temporary FPS drop is expected.
- No GPU texture is copied back to the CPU by this probe.

After the park texture is identified, the diagnostic D3D11 observer can be
removed from normal builds. The finished path will use a GPU-to-GPU transfer
and apply Economy, Balanced, Quality, and Ultra scheduling limits.
