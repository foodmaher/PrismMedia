# Version 3.12.1: cursor-alignment hotfix

ETS2/ATS draws its own software cursor in game menus while the plugin uses the
Win32 pointer for ImGui. The former overlay input hook discarded every buffered
DirectInput mouse event. Consequently, moving the pointer over the plugin left
the game cursor frozen at its previous menu position and the two cursors became
visibly separated.

While the plugin menu is open, the hook now:

- Retains only DirectInput X/Y movement so the game cursor follows the same
  physical mouse position as the Win32/ImGui cursor.
- Hides the redundant Win32 cursor image while telemetry reports a game menu
  or paused state, leaving the synchronized SCS cursor as the one visible
  pointer. During active driving, the Win32 cursor remains visible because the
  game does not draw its menu cursor.
- Removes mouse buttons and wheel events before the game receives them.
- Gives the relevant Win32 pointer messages to ImGui but does not forward them
  to the underlying SCS window, avoiding duplicate movement or clicks.
- Uses an atomic overlay-input state because input polling and rendering can
  occur on different threads.

Closing the plugin restores the normal, unfiltered game input path. This fix
does not change gamepad navigation or the configured plugin-menu binding.
